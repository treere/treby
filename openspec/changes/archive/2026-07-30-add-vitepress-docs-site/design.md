## Context

Treby currently has 22 screenshots in `docs/screenshots/` embedded inline in README.md. The README is a monolith covering features, setup, and screenshots — it loads slow (especially with images) and offers no search. There is no dedicated site for potential users or contributors to evaluate the project.

The site will be built with Vitepress, a Vue-powered static site generator optimized for documentation. It runs on Node.js (already present in the repo via esbuild/Tailwind), produces pure static output, and has built-in full-text search, responsive design, and theming.

## Goals / Non-Goals

**Goals:**
- Professional landing page that communicates Treby's value proposition in seconds
- Feature documentation pages (one per major feature) with screenshots and descriptions
- Getting-started guide and architecture overview
- Built-in full-text search across all content
- Screenshot generation script using Playwright for reproducibility
- GitHub Actions deployment to GitHub Pages
- AGENTS.md updated to remind contributors to keep the site in sync

**Non-Goals:**
- No interactive demos or embedded app instances
- No user authentication or comments
- No i18n (the app has it, but the docs site is English-only for now)
- No blog or changelog (can be added later)
- No custom domain configuration (stays under `treere.github.io/treby/` for now)

## Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| **Framework** | Vitepress | Built-in search, beautiful default theme, minimal config, outputs static HTML. Already compatible with the repo's Node.js toolchain. |
| **Site location** | `site/` directory | Clean separation from Elixir code. Vitepress needs its own `package.json` and config. Not interleaved with Phoenix assets. |
| **Screenshot strategy** | Local Playwright script | CI screenshot generation would require a full Phoenix + PostgreSQL + MinIO setup in CI — slow and brittle. A local script the developer runs when features change is pragmatic. Screenshots are committed as PNGs. |
| **README image removal** | Replace with link to site | Eliminates the 5MB+ of inline images from the README. Keeps README as a quickstart reference, not a feature tour. |
| **Base URL** | `/treby/` | GitHub Pages project sites are served from `https://<user>.github.io/<repo>/`. Vitepress `base` config handles this. |
| **Theme** | Vitepress default with custom CSS overrides | The default theme is already professional. Custom CSS tailors colors and typography to Treby's brand without a full custom theme. |
| **Deployment** | `actions/deploy-pages` | Official GitHub Pages deploy action. Pair with `actions/upload-pages-artifact` for zero-config deployment. |

## Screenshot Script Design

The script (`scripts/screenshots.mjs`) will launch the Phoenix app — no separate server needed since the app uses SQLite... wait, it uses PostgreSQL. For local development, the developer needs:

- PostgreSQL running with seeded data (`mix setup`)
- Phoenix server running (`mix phx.server`)
- The script then connects and captures:

```
Login → Dashboard → Jobs List → Pipeline Kanban → Candidates List →
Candidate Detail → Analytics → Settings Hub → Pipeline Settings →
Team Settings → Custom Fields → Branding → Public Careers →
Public Job Detail → Apply Form → Register Page → Add Note Form →
Add Candidate Form → Job Detail
```

Each screenshot uses a consistent viewport (1280×900), waits for `networkidle`, and saves with a sequential naming convention (`01-dashboard.png`, etc.).

## Risks / Trade-offs

| Risk | Mitigation |
|------|------------|
| Screenshots become stale if features change | AGENTS.md reminder + screenshot script makes it easy to regenerate |
| Vitepress version drift | Pin vitepress version in `package.json` |
| GitHub Actions token/Pages permission | Use `GITHUB_TOKEN` with `contents: write` and `pages: write` permissions |
| Large PNGs bloat the repo | Keep screenshots under 200KB each via Playwright `fullPage: false` + quality settings. Consider PNG optimization in CI later if needed. |
| Node.js version incompatibility | Pin Node 20 in both `package.json` `engines` and CI workflow |
