## Context

Registration (`GET /register`, `POST /register → /register/verify`, `POST /register/verify` → `RegistrationController`) and candidate portal (`/:slug/portal/login` → `POST /portal/login`, `GET /:slug/portal/verify`, `POST /portal/verify` via `CandidateOtpController`) both use a 6-digit OTP via `Swoosh` email. The OTP is generated by `RegistrationVerification.generate_code/1` and `CandidatePortal` with 10-minute expiry and `rate_limited` guard. Live testing showed the user must leave the product to fetch the code from `/dev/mailbox` (dev) or inbox (prod), copy `366470` / `785913` / `222693`, then return to `/register/verify` to paste. No countdown, no `Resend` disable, and `rate_limited` surfaces as generic `Please wait a moment`. Candidate portal repeats the same pattern.

Current `verify.html.heex` shows a single `textbox "Verification code"` and `Verify email` button plus `Resend code` (always enabled). No paste-friendly 6-input, no helper `Code sent to x@…`, no dev mailbox link. `RegistrationVerification` stores `code_hash` + `expires_at` and throttles via `last_sent_at`.

## Goals / Non-Goals

**Goals:**
- Make the OTP step discoverable and forgiving: visible `Code sent to …` helper, `Resend` countdown (60s), and `Try again in {s}s` for `rate_limited`.
- Add dev affordance: when `Mix.env() == :dev`, show `Open mailbox` link to `/dev/mailbox`.
- Add paste-friendly UX: single input that accepts 6-digit paste, plus auto-advance if split into 6 inputs (deferred to implementation choice).
- Apply the same hardening to candidate portal `/:slug/portal/verify` and keep invite `/:invite/:token` unaffected.

**Non-Goals:**
- No change to OTP security model (6-digit, 10-min, hash storage, email delivery).
- No magic-link alternative.
- No change to tenant slug generation or `Accounts.email_registered?` duplicate check.

## Decisions

**Decision 1 — Resend countdown via server `last_sent_at` + client tick (chosen) over pure client timer.**
- *Chosen:* `RegistrationController.verify` and `CandidateOtpController` already set `registration_email` / `portal_email` in session and `RegistrationVerification` knows `last_sent_at`. Pass `resend_available_at = last_sent_at + 60s` to the template, render `Resend code (available in 60s)` disabled with `phx-hook=".ResendCountdown"` that ticks every second and enables at 0. On `rate_limited`, compute `retry_after = max(1, DateTime.diff(resend_available_at, now))` and flash `Try again in {retry_after}s`.
- *Why:* Server is source of truth for rate limit; client just animates. No extra endpoint.
- *Alternative:* Pure client 60s after click — rejected because server throttles independently.

**Decision 2 — Single input with paste support (chosen) over 6 separate inputs.**
- *Chosen:* Keep single `textbox "Verification code"` but add `phx-hook=".OtpPaste"` that on `paste` strips non-digits, fills the input, and auto-submits if 6 digits. Also handle `input` event to strip non-digits and limit to 6.
- *Why:* Minimal template change, works with existing `Registration.changeset` and `CandidateOtp` validation (single `code` param). 6-input split would require 6 fields and JS sync.
- *Alternative:* 6-input auto-advance — more code, same UX; can be added later if desired.

**Decision 3 — Dev mailbox link (chosen) over no dev affordance.**
- *Chosen:* In `verify.html.heex` and `portal/verify.html.heex`, when `Application.get_env(:treby, :env) == :dev` or `Mix.env() == :dev` (compile-time check via `if Mix.env() == :dev` in template or controller assign `is_dev`), show `Open mailbox` link to `/dev/mailbox`.
- *Why:* Hardening is most needed in dev/self-hosted; prod shows helper text `Check your email (including spam)` instead.

## Risks / Trade-offs

- **[Risk] Countdown drift between server and client** → Mitigation: client recomputes `remaining = max(0, resend_available_at - now())` on mount from server timestamp, not from click time.
- **[Risk] Paste hook conflicts with browser autofill** → Mitigation: hook only on `paste` event, not on `input`; autofill still works via single field.
- **[Risk] Rate-limit flash overlaps with countdown disabled state** → Mitigation: on `rate_limited`, redirect to `verify` with `resend_available_at` still in future, so button stays disabled and flash shows `Try again in {s}s`.

## Migration Plan

- No migration. Deploy: `mix compile`. Rollback: revert templates and hooks.
